## Re-verification round (post-merge audit)

A second pass checked every plan's done criteria mechanically and reviewed the user flows the changes touched. Findings fixed before release:

- **Plan 001 broke two legitimate GUI flows** (its own STOP condition): "Open File / Show in Folder" after an export to a user-chosen folder, and the Settings "Open" action for the project config, both target paths outside the library root. Fixed by registering export destinations as app-produced allowed roots and adding a narrow config-file exception (the config's parent directory is never added wholesale). Regression tests added.
- **`--render` without Playwright** failed the whole capture with a traceback (the once-per-capture check moved outside the per-page fallback). The CLI now exits 2 with install instructions, and the GUI bridge rejects the start with a clear error; tests added.
- **`DomainLock.acquire` could raise `PermissionError`** on Windows when a contender was deleting the lock file (sharing violation). It now retries briefly and then reports `LockHeldError`. The storm test is stable across 30 consecutive runs.
- **`DomainLock._is_stale` no longer steals on an unreadable lock** unless the 15-minute mtime window has expired (conservative liveness, matching plan 017's principle).
- **`capture_many` mid-crawl cancellation** surfaced the engine's `RuntimeError` instead of marking the batch cancelled; fixed and tested.
- **Release mechanics:** version bump reached `__init__`, CLI fallback, docs/frontend version constants, `uv.lock`, `server.json`, README badge, and tests; brand assets regenerated; prebuilt GUI bundle rebuilt and committed at 11.4.0.

Residual, deliberately not fixed: one high `source-map-js` advisory in `docs/` (fix available, not critical); render mode now fails fast rather than silently falling back; coverage gate has 1 point of headroom.
