## Why this matters

`requires-python = ">=3.10"` with no upper bound, but CI tests only 3.10 and 3.12, and the trove classifiers list 3.10/3.11/3.12 — users on 3.11 and 3.13 install untested wheels, and the PyPI page under-promises support while README badges claim "Python 3.10+". 3.13 is the current CPython; a regression there ships silently today.

## Current state

- `.github/workflows/ci.yml` (verified at HEAD ea307bd): `python-version: ["3.10", "3.12"]` — note the duplication the audit flagged: 3.10 pinned twice in effect because 3.11 is missing.
- `pyproject.toml` classifiers (verified):
```
    "Programming Language :: Python :: 3.10",
    "Programming Language :: Python :: 3.11",
    "Programming Language :: Python :: 3.12",
```
- `uv.lock` resolves fine across the board; no upper bound in `requires-python`.
- Known risk: some dev/runtime dep may not have 3.13 wheels (most cited are pure-Python or ship abi3/wheels; `mcp`, `textual`, `requests`, `bs4`, `markdownify`, `lxml` (C extension — has 3.13 wheels since 5.x), `fpdf2`, `pywebview` are all fine on 3.13 today).
